# GPI Control & HR Platform

**Назначение:** единая цифровая HR-платформа для сотрудников, руководителей и HR. Принципы: **открытость, надёжность, результат**.

Это **демонстрационный проект для локальной сети**. Данные вымышленные. Не используйте его с реальными персональными данными без дополнительной проверки безопасности, настройки HTTPS и смены тестовых паролей.

## Что есть в системе

| Требование | Реализация |
|---|---|
| Вход и роль | Отдельные аккаунты сотрудника, руководителя, HR |
| Профиль | Ф.И.О., компания, должность, отдел, руководитель, дата приёма, остаток отпуска, обучение, уведомления |
| Заявки | Отпуск и аванс → отправка → согласование → статус → история → уведомление |
| Обучение | 8 готовых курсов, 49 уроков, 196 вопросов; заявки, результаты и прогресс |
| AI Jana | Ответы **только по разрешённым статьям базы знаний**, ссылка на статью; если подтверждённого ответа нет — «Я не знаю» |
| Уведомления | Отдельный раздел и уведомления об HR-заявках и обучении |
| HR | Редактирование HR-профилей, согласование заявок, управление статьями, сотрудники, обучение |
| Руководитель | Просмотр/согласование заявок сотрудников своего подразделения, обучение, задания |
| Безопасность | HR-профили и заявки изолированы на сервере; сотрудники/руководители получают только свой подразделенческий срез GPI |

Сохранились дополнительные разделы прошлой версии: **задачи, GPI, рейтинг, награды, аналитика и личные сообщения**, а также оформление в зелёно-белой палитре, вдохновлённой Jańa Post. GPI Control не является официальным продуктом Jańa Post.

## Запуск

1. Установите **Python 3.9+** на основной компьютер. Для Windows при установке отметьте *Add Python to PATH*.
2. Если обновляете существующий сайт: **остановите сервер, сделайте копию `gpi_data.sqlite3` и не заменяйте этот файл** содержимым архива.
3. Распакуйте файлы и запустите **`START_WINDOWS.bat`** либо `python server.py`.
4. На этом компьютере откройте **http://127.0.0.1:8000**.
5. Другие компьютеры в той же частной Wi-Fi сети: `http://IP_ОСНОВНОГО_КОМПЬЮТЕРА:8000` (получите адрес с помощью `ipconfig`).
6. При запросе брандмауэра разрешайте доступ только для **частной сети**. Не пробрасывайте порт в интернет.

**Не открывайте `index.html` двойным кликом:** необходим Python-сервер.

### Демонстрационные входы

| Роль | Логин | Пароль |
|---|---|---|
| HR | `admin` | `admin123` |
| Руководитель отдела «Продажи» | `manager` | `manager123` |
| Сотрудник отдела «Продажи» | `employee` | `employee123` |

Логины и пароли **только для демонстрации**. Перед использованием с непубличной информацией их нужно заменить. В исходном `seed.json` присутствуют только **вымышленные** сотрудники, курсы и документы.

## HR-профиль и права

- **Сотрудник** видит свою HR-карточку с датой приёма, руководителем, остатком дней и прогрессом обучения. Может подавать заявки на отпуск или аванс, отслеживать решения и читать статьи, доступные его роли.
- **Руководитель** видит заявки сотрудников своего подразделения, может одобрять или отклонять их. Не может менять чужой HR-профиль или базу знаний.
- **HR** просматривает все заявки, редактирует HR-профили через «Профиль → HR-редактор профилей», публикует и изменяет статьи базы знаний. Изменение HR-профиля не переименовывает учётную запись или объект сотрудника в модуле GPI; это отдельная HR-карточка.

## Заявки

1. Откройте **«HR-заявки»**.
2. Выберите **«Отпуск»** (даты) или **«Аванс»** (сумма в тенге), при желании добавьте комментарий.
3. Нажмите **«Отправить заявку»**. Статус: «На рассмотрении».
4. Руководитель отдела или HR в очереди заявок выбирает «Одобрить» или «Отклонить».
5. Сотрудник видит **статус, историю изменений и уведомление**. Одобренный отпуск уменьшает остаток отпускных дней. Реальной выплаты аванса нет.

В этой учебной версии дни считаются **календарными, включая обе даты**; это упрощение для демонстрации и не является правовым или кадровым расчётом.

## AI Jana и база знаний

Для строгого соответствия ТЗ ответы AI Jana теперь формируются **по статьям внутренней HR-базы**, а не по догадкам языковой модели.

- Источники можно открыть по ссылке `http://АДРЕС_САЙТА:8000/kb/article/ID` — сервер проверяет, имеет ли текущий пользователь право читать статью.
- Ответ AI Jana показывает текст разрешённой статьи и ссылку «Источник». Если уверенного совпадения с доступными документами нет, ответ: «Я не знаю: в доступной базе знаний нет подтверждённого ответа».
- HR управляет статьями в разделе **«База знаний»**: добавить, изменить, удалить, выбрать видимость (все, руководители, HR или отдельный отдел).
- Стартовые статьи — **демонстрационные**, а не официальные регламенты компании. Замените их утверждёнными HR-документами перед реальным использованием.

**О своей ИИ-модели:** выбор локальной Ollama и импорт собственной GGUF-модели из предыдущей версии сохранён в настройках HR. Однако **строгий HR-режим ответов использует только базу знаний** — выбранная Ollama не требуется для ответов по HR. Это специально сделано, чтобы AI Jana не придумывал несуществующие правила. Программный интерфейс локальной модели сохранён для дальнейшего развития, без обращений к OpenAI API.

## Обучение

- 8 курсов, 49 текстовых уроков и **196 поурочных вопросов** (по 4 вопроса на урок); дополнительные итоговые тесты курсов.
- Сначала сотрудник подаёт заявку на обучение; руководитель или HR одобряет её.
- Сотрудник читает материал, затем сдаёт тест. Правильные **3 ответа из 4** означают зачёт урока (≥75%).
- Лучший результат пересдачи и прогресс записываются в SQLite; уведомления показывают изменение статуса и завершение курса.
- Курсы, созданные вручную, пока не получают автоматически написанные уроки или тесты.

## Архитектура

```text
index.html                     интерфейс: HTML + CSS + JavaScript
server.py                      Python HTTP API, авторизация, роли, HR, тесты, SQLite
seed.json                      стартовые демоданные сотрудников и GPI
starter_courses.json           8 готовых курсов
starter_lesson_content.json    49 текстовых уроков
starter_lesson_quizzes.json    196 поурочных вопросов
starter_quizzes.json           итоговые тесты курсов
START_WINDOWS.bat              запуск сервера на Windows
BACKUP_DB.py                   создание резервной копии SQLite
README.md                      эта инструкция

gpi_data.sqlite3               база данных, создаётся при запуске, в архив не включена
```

Дополнительные таблицы SQLite: `hr_profiles`, `hr_requests`, `hr_request_history`, `hr_notices`, `hr_knowledge`. При запуске старой базы таблицы **создаются автоматически, без удаления старых курсов, задач, аккаунтов, сообщений и оценок**. Отдельные серверные API проверяют доступ к профилю, заявкам, базе знаний и источникам. В `/api/state` пользователям без роли HR выдаются данные только их подразделения, а сервер сохраняет неизменными записи других подразделений.

## Безопасность и ограничения

- Демо-сервер использует **HTTP без шифрования**, поэтому предназначен исключительно для частной учебной LAN, **не для интернета и не для продуктивной работы с кадровыми персональными данными**.
- В проекте есть ролевые ограничения, хэширование паролей и проверки разрешений, но **нет** полноценного промышленного аудита безопасности, HTTPS, интеграции с реальной зарплатой/кадровой системой и электронной подписи.
- Не публикуйте тестовые пароли, не загружайте настоящие персональные данные и не заменяйте рабочую базу демофайлом.
- Остановите сервер и скопируйте `gpi_data.sqlite3` для резервного хранения или выполните `python BACKUP_DB.py` (использует SQLite Backup API). Резервные копии сохраняются в папку `backups`.

### Если не запускается

- Убедитесь, что установлен Python и сервер запущен в папке, где находятся `server.py`, `index.html` и JSON-файлы.
- При `Failed to fetch` проверьте адрес, порт 8000, одну Wi-Fi сеть и разрешения брандмауэра.
- Для восстановления HR используйте `ВОССТАНОВИТЬ_HR.bat` локально на основном компьютере.

## Название роли HR

Роль с полным доступом в интерфейсе называется **HR**. Демо-пользователь: **HR**, вход `admin / admin123`. Для существующих установок логин `admin` и внутренний идентификатор роли `admin` сохранены намеренно: это обеспечивает совместимость с текущей базой данных и проверками доступа. При первом запуске старое демонстрационное имя «Администратор Системы» автоматически изменяется на «HR» (другие имена не затрагиваются). Сброс пароля: `ВОССТАНОВИТЬ_HR.bat`.

## Новый модуль: подтверждение заданий и штрафы GPI

В разделе «Задания» появился полный рабочий процесс:

1. HR или руководитель создаёт задание сотруднику (новая задача начинается с нулевого подтверждённого прогресса).
2. Сотрудник нажимает «Принять».
3. Вносит фактический объём работы кнопкой «Внести результат». Это **заявленный**, а не подтверждённый результат.
4. Нажимает «Сдать на проверку». HR или руководителю подразделения приходит уведомление.
5. HR или руководитель нажимает «Принять результат» либо «Доработать»; при доработке можно написать замечание.
6. Только после принятия результата сервер обновляет подтверждённый прогресс задачи, её статус, GPI и место в рейтинге. Частично подтверждённую задачу можно продолжить.

**Штраф за просрочку**: сервер начисляет одно виртуальное списание **−10 GPI-баллов** за каждую просроченную задачу, если она не была подтверждена к концу даты дедлайна (по дате сервера). Штраф виден в карточке задания и в истории списаний; он вычитается из GPI сотрудника и влияет на рейтинг. Списание делается **только один раз на задачу** и сохраняется в SQLite отдельно от задач. Оно не является денежным штрафом или вычетом из зарплаты. Повторное открытие сайта не удваивает штраф.

Заявки и результаты хранятся в новых таблицах `task_workflows`, `task_penalties`, `task_audit` базы `gpi_data.sqlite3`. Они автоматически создаются при первом запуске обновлённого сервера. Не удаляйте старую базу: так сохранятся сотрудники, рейтинги, курсы и HR-заявки. Сделайте резервную копию перед обновлением.

**Важное отличие:** старый ввод фактического прогресса напрямую из интерфейса или изменения в JSON больше не могут изменить подтверждённый результат; такие запросы сервер отвергает. Старые подтверждённые численные показатели задач остаются как исторические данные.

**Настройка штрафа:** константа `TASK_LATE_PENALTY=10` в `server.py`. Для другого размера штрафа измените её до запуска сервера; ранее начисленные списания останутся по прежней ставке. Для реального HR-процесса настройку политики штрафов и возможность оспаривания должен утвердить ответственный HR. Система предназначена для демонстрации и не должна автоматически удерживать реальные деньги из заработной платы.
